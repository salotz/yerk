# Plan: domain model glossary

## Context

Product vocabulary is concentrated in `design/domain-and-near-term.md` and
scattered how-tos. Operators and agents need a **single canonical glossary**
(project, catalog, domain, workspace, replica, presence/change, `yerk://`,
materialize, placement, …).

## Goals

1. One durable glossary page.
2. Thin cross-links from concept hubs (not a second full domain essay).
3. Optional alignment with `yerk context` vocabulary strings.

## Non-goals

- Renaming the design spine (separate plan).
- Changing CLI flag names.

## Phases

0. Lock home path + term list.  
1. Write glossary.  
2. Link pass.  
3. Close-out.

## Success criteria

- [ ] Glossary exists and is linked from docs hub / explanation.
- [ ] No contradictory definitions vs ADRs.
- [ ] Plan removable at close.
